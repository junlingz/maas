# 框架扩展测试功能核心需求

> 版本：v1.3  
> 范围：框架扩展列表中的独立「测试」弹窗  
> 原型边界：当前使用预置用例和示例结果体现能力，生产环境需接入真实测试服务。

## 1. 目标

在不删除、不改名现有「调试」功能的前提下，为每个扩展版本增加独立「测试」按钮。用户在弹窗内查看测试工具与用例、启动自动化测试，并查看测试结果及性能指标报告。

## 2. 核心功能

1. 扩展版本操作区新增「测试」按钮，点击后以弹窗打开，交互形式与调试弹窗保持一致。
2. 弹窗只提供三类测试工具：单元测试运行器、集成测试运行器、性能基准测试工具。
3. 每类工具提供平台内置测试用例；用例至少展示用例 ID、测试目标和预期结果，可展开查看。
4. 用户点击「开始测试」后，系统按“单元测试 → 集成测试 → 性能测试”的固定顺序自动执行全部用例，无需逐项操作。
5. 执行完成后，在同一弹窗生成并展示测试结果与性能指标报告。

## 3. 结果展示

- 总体结论：通过或未通过。
- 分类结果：每类测试的通过数、用例总数和耗时。
- 用例结果：每条用例的状态、实际结果和耗时。
- 性能指标：启动耗时、处理吞吐、P95 延迟、内存峰值。
- 本期不提供测试用例下载、报告下载或 PDF 生成功能。

## 4. 规则

- 「调试」与「测试」是两个独立入口，测试功能不得替换或影响原调试功能。
- 调试未通过时允许查看工具和用例，但「开始测试」不可用。
- 重新测试时清空本次旧结果并重新执行全部用例。
- 上传新版本后不得继承旧版本的测试结论。
- 任一必测用例失败，则总体测试结论为未通过。
- 只有当前版本调试通过且自动化测试通过，才允许启用。

## 5. 最小验收标准

1. 列表同时存在「调试」和「测试」按钮，且均打开独立弹窗。
2. 测试弹窗可查看三类工具及对应内置用例。
3. 点击一次「开始测试」即可自动完成三类测试。
4. 完成后可查看总体结论、分类结果、逐条用例结果和四项性能指标。
5. 页面不存在测试用例下载、报告下载或 PDF 生成入口。
